# 🛗 Elevator Simulation

### 한성대학교 상상관 엘리베이터 시뮬레이션

Java를 활용하여 엘리베이터의 이동 및 운행 과정을 구현하는 자료구조·알고리즘 팀 프로젝트입니다.

한성대학교 상상관의 엘리베이터를 배경으로 실제 엘리베이터의 동작을 시뮬레이션하고, 시각적인 인터페이스를 통해 운행 과정을 확인하는 것을 목표로 합니다.

## 🚀 4. 프로젝트 실행 방법

### 4.1 저장소 복제

CMD에서 다음 명령어를 실행합니다.

```bash
git clone <저장소-주소>
```

### 4.2 Eclipse로 가져오기

1. Eclipse 실행
2. `File → Import` 선택
3. `General → Existing Projects into Workspace` 선택
4. `Select root directory`에서 복제한 프로젝트 폴더 지정
5. 프로젝트 선택 후 `Finish`
6. JDK 및 Build Path 확인
7. 메인 클래스를 실행하여 프로그램 시작

### 4.3 실행 시 주의사항

- 지정된 JDK 버전을 사용합니다.
- 프로젝트에 필요한 이미지 파일을 삭제하지 않습니다.
- 프로젝트 실행에 오류가 발생하면 팀원에게 공유합니다.

## 🌿 5. Git 브랜치 전략

협업 시 각자 작업할 기능에 맞는 브랜치를 생성합니다.

### 브랜치 구성

| 브랜치 | 설명 |
|---|---|
| `main` | 안정적으로 동작하는 통합 코드 |
| `feature/intro` | 시작 화면 및 스토리라인 개발 |
| `feature/ui` | Swing GUI 개발 |
| `feature/algorithm` | 엘리베이터 알고리즘 개발 |
| `fix/기능명` | 버그 수정 |

### 기본 원칙

1. `main` 브랜치에서는 직접 개발하지 않습니다.
2. 각 기능은 별도의 브랜치에서 작업합니다.
3. 기능이 완성되면 Pull Request를 생성합니다.
4. 팀원들과 변경 사항을 확인한 후 병합합니다.
5. 제출용 ZIP은 안정적으로 통합된 `main` 브랜치를 기준으로 생성합니다.

## 💻 6. Git 협업 방법

Git 명령어는 Windows CMD를 기준으로 작성했습니다.

### STEP 1. 최신 코드 가져오기

작업을 시작하기 전에 최신 코드를 가져옵니다.

```bash
git switch main
git pull origin main
```

### STEP 2. 새로운 브랜치 생성

담당 기능에 맞는 브랜치를 생성합니다.

```bash
git switch -c feature/ui
```

`feature/ui`는 예시이므로 실제 담당 기능에 맞게 변경합니다.

### STEP 3. 코드 작성

Eclipse에서 담당 기능을 개발합니다.

작업 후 CMD에서 변경된 파일을 확인합니다.

```bash
git status
```

### STEP 4. 변경 사항 커밋

```bash
git add .
git commit -m "feat: UI 기능 구현"
```

커밋 전 불필요한 파일이 포함되지 않았는지 확인합니다.

### STEP 5. GitHub에 업로드

```bash
git push -u origin feature/ui
```

### STEP 6. Pull Request 생성

1. GitHub 저장소에 접속합니다.
2. 작업한 브랜치에서 `Compare & pull request`를 선택합니다.
3. 변경 사항과 작업 내용을 작성합니다.
4. 팀원들과 코드를 검토합니다.
5. 문제가 없다면 `main` 브랜치에 병합합니다.

### STEP 7. 다음 작업 준비

병합이 완료되면 다시 최신 코드를 가져옵니다.

```bash
git switch main
git pull origin main
```

이후 새로운 기능 브랜치를 생성하여 작업합니다.

## 📝 7. Commit Message 규칙

커밋 메시지는 변경 내용을 알아볼 수 있도록 작성합니다.

| 구분 | 설명 | 예시 |
|---|---|---|
| `feat` | 새로운 기능 추가 | `feat: 엘리베이터 호출 구현` |
| `fix` | 오류 수정 | `fix: 층 이동 오류 수정` |
| `docs` | 문서 수정 | `docs: README 수정` |
| `style` | 코드 스타일 정리 | `style: 코드 들여쓰기 정리` |
| `refactor` | 코드 구조 개선 | `refactor: 이동 로직 분리` |
| `test` | 테스트 추가 및 수정 | `test: 엘리베이터 이동 테스트` |
| `chore` | 기타 설정 및 관리 | `chore: gitignore 추가` |

### 커밋 예시

```bash
git commit -m "feat: 시작 화면 구현"
git commit -m "feat: 엘리베이터 이동 알고리즘 추가"
git commit -m "fix: 버튼 클릭 오류 수정"
git commit -m "docs: 협업 규칙 추가"
```

하나의 커밋에는 가능한 한 하나의 작업 목적만 담습니다.

## 🤝 8. 협업 규칙

### 작업 시작 전

- 최신 코드를 Pull합니다.
- 자신의 담당 기능을 확인합니다.
- 새로운 작업 브랜치를 생성합니다.

### 작업 중

- 다른 팀원의 작업 파일을 수정해야 한다면 먼저 공유합니다.
- 기능 단위로 커밋합니다.
- 작업 중 발생한 오류는 팀원들과 공유합니다.
- 이미지와 리소스 파일의 경로를 일관되게 관리합니다.

### 작업 완료 후

- 기능이 정상적으로 동작하는지 테스트합니다.
- GitHub에 변경 사항을 Push합니다.
- Pull Request를 생성합니다.
- 코드 검토 후 통합합니다.
- 협업 내용을 기록합니다.

### 주의사항

**다른 팀원의 코드를 임의로 덮어쓰지 않습니다.**

Merge Conflict가 발생하면 관련 팀원들과 변경 사항을 확인한 후 해결합니다.

## 📦 9. e-class 협업 결과물 제출

본 프로젝트는 GitHub를 통해 협업하며, 교수님이 개발 과정을 확인할 수 있도록 e-class 게시판에 단계별 결과물을 ZIP 파일로 업로드합니다.

### 제출 원칙

1. 협업 진행 단계에 따라 ZIP 파일을 제출합니다.
2. 제출 당시의 프로젝트 상태를 보존합니다.
3. 게시글에 협업 일자, 참여 인원 및 변경 사항을 작성합니다.
4. 각 팀원의 역할과 작업 내용을 기록합니다.
5. 가능하면 관련 GitHub 커밋 또는 Pull Request 링크를 함께 남깁니다.

### ZIP 파일명 예시

```text
01_프로젝트초기구성.zip
02_UI구현.zip
03_알고리즘구현.zip
04_기능통합.zip
05_최종제출.zip
```


### 게시글 작성 형식

**제목:** [N차 협업] 작업 내용

**내용:**

- 협업 일자:
- 팀원별 담당 작업:
- 이번 협업에서 구현한 기능:
- 발생한 문제와 해결 과정:
- 다음 협업 계획:
- GitHub 커밋 또는 PR 링크:

**첨부:** 해당 시점의 프로젝트 ZIP

ZIP 제출 시 GitHub 저장소의 `main` 브랜치에서 `Code → Download ZIP` 기능을 사용할 수 있습니다.

교수님이 Eclipse 프로젝트 실행에 필요한 추가 파일을 요구한 경우 해당 파일도 포함합니다.
